상태: **테스트 및 빌드 통과**. 기록 날짜: 2026-10-23. 검증 환경: Intel Mac, macOS 15.7.9, Swift 6.2.4 / Xcode. 최소 배포 버전은 macOS 14입니다.

이번 버전은 macOS 14 이상의 네이티브 ImageIO를 통한 JPEG XL 입력과 독립적인 열기 암호 및 편집 암호를 지원합니다. 암호화 설정은 오른쪽 패널 안의 기본적으로 접힌 영역에 있으며 제목 행 전체를 클릭할 수 있습니다. 이번 전체 실행에서 XCTest 58개가 모두 통과했으며 실패 0개, 건너뜀 0개입니다. 로컬 네이티브 PDF 쓰기 인터페이스에서는 열기 암호가 17–31자일 때 owner 암호가 무효가 될 수 있음을 확인했습니다. 앱은 두 암호 모드의 길이 사전 검사로 이 문제를 피합니다. 관련 보안 경계는 아래에 설명되어 있습니다. 이번 로그는 `test-results.txt`에 있습니다.

## 제공 파일

- `dist/FolioPDF.app`: 네이티브 AppKit 창, SwiftUI 인터페이스, 시스템 PDFKit / Vision / ImageIO를 사용합니다. 앱 파일명에 버전 번호를 넣지 않으며, 버전은 앱 메타데이터에 기록합니다.
- `dist/FolioPDF-1.4-macOS.zip`: x86_64와 arm64가 포함된 범용 앱 패키지이며 `lipo -archs`로 확인했습니다.
- `dist/FolioPDF-1.4-source.zip`: Xcode에서 열 수 있는 Swift Package 소스이며 테스트, 스크립트, 사용 설명, 인터페이스 스크린샷이 포함됩니다.
- 패키징 스크립트는 로컬 ad-hoc 서명을 사용하며 `codesign --verify --deep --strict`를 통과했습니다. Developer ID 공증은 포함하지 않습니다. 내부 버전은 1.4(build 5)이며 앱 파일명은 여전히 `FolioPDF.app`입니다.

OCR 테스트에서는 실제로 생성한 텍스트 이미지를 사용하여 출력 PDF의 텍스트를 추출할 수 있는지 확인하고, 숨겨진 텍스트가 페이지 렌더링을 바꾸지 않는지 검증합니다. 테스트는 macOS 시스템 서비스에 접근할 수 있는 환경에서 실행해야 합니다. 제한된 실행 샌드박스의 CoreVideo 오류를 통과로 취급하지 않습니다.

### 두 암호의 합격 조건

| 모드 | 일반 독자 | 편집 암호 보유자 |
|---|---|---|
| 열기 암호만 사용 | 빈 암호나 잘못된 암호로는 열 수 없으며, 올바른 열기 암호로 모든 작업 권한을 얻습니다 | 별도의 편집 암호를 설정하지 않습니다 |
| 편집 암호만 사용 | 암호 없이 읽을 수 있으며 내용 수정, 주석, 양식 작성, 페이지 구성이 금지됩니다 | 편집 암호로 owner 전체 권한을 얻습니다 |
| 두 암호 모두 사용 | 열기 암호로 제한된 user 권한을 얻습니다 | 편집 암호로 파일을 직접 열고 owner 전체 권한을 얻습니다 |

두 암호를 함께 사용할 때는 서로 달라야 합니다. 세 모드 모두 인쇄, 복사, 접근성 기능을 허용합니다. 제한 모드에서는 내용 수정, 주석, 양식 작성, 페이지 삽입/삭제/회전을 허용하지 않습니다. 권한 제한은 리더가 이를 준수해야 적용되며, “절대로 수정 불가능”하다는 보장이 될 수는 없습니다.

암호에는 인쇄 가능한 ASCII 문자만 사용할 수 있습니다. 안전하게 지원되는 범위는 열기 암호만 사용 시 1–32자, 편집 암호만 사용 시 1–32자, 두 암호 모드에서 열기 암호 1–16자와 편집 암호 1–32자입니다. 두 암호 모드의 조건부 제한은 인터페이스에 명확히 표시되며 내보내기 사전 검사에서 적용됩니다. 범위를 넘으면 즉시 오류를 반환하며 암호를 자르거나 앞뒤 공백을 바꾸거나 보호 수준을 낮춰 출력하지 않습니다.

이미 열린 PDF에서 `unlock(withPassword:)`를 호출하면 owner 암호가 잘못되어도 `true`가 반환될 수 있습니다. 따라서 합격 여부는 `permissionsStatus`와 모든 권한 비트를 확인해야 합니다. 제한된 reader는 user/51, owner는 owner/255이며, 열기 암호만 사용한 reader는 user/255입니다. 편집 암호만 있는 파일은 자동으로 열리며 기록에 넣을 페이지 수를 읽을 때 owner 잠금 해제가 필요하지 않습니다.

## 인터페이스 및 언어

- 현재 리소스에는 문구 292개 × 16개 언어가 있으며, 실제 인터페이스 문구는 281개입니다. `check-localization.py`를 통과했으며 패키지의 언어 리소스는 소스 파일과 바이트 단위로 같습니다.
- 기본적으로 시스템을 따릅니다. 언어 순서는 사용자가 지정한 순서와 같습니다: 简体中文, English, 繁體中文, 日本語, 한국어, Français, Deutsch, Español, Italiano, Português (Brasil), Русский, العربية, हिन्दी, Türkçe, Nederlands, Polski.
- 아랍어의 기본 창과 설정 창은 모두 RTL 레이아웃을 사용합니다. 파일 이름, 이미지, PDF 내용은 그대로 유지됩니다. 책갈피 TAB 텍스트 편집기는 인터페이스 파일의 편집 의미가 바뀌지 않도록 LTR 구조를 유지합니다.
- 이번에는 앱을 다시 실행하고 실제 NSView를 렌더링하여 중국어 밝은 모드의 기본 접힌 상태와 두 암호 펼친 상태, 독일어 어두운 모드의 긴 문구, 아랍어 RTL, 편집 암호만 사용하는 상태를 확인했습니다. 입력 항목과 설명은 정상적으로 줄바꿈되며 겹침이나 누락된 글자는 보이지 않았습니다. 화면을 넘는 내용은 오른쪽 패널과 함께 스크롤됩니다. 스크린샷은 아래 표에 있습니다.
- “문서 정보”, “PDF 암호화”, “여백 및 해상도” 등의 접을 수 있는 제목에는 행 전체 크기의 Button을 사용합니다. 레이블을 전체 너비로 확장하고 사각형 클릭 영역을 정의했습니다. 왼쪽 작업 공간 탐색과 하단 설정 항목의 클릭 영역도 확대했습니다. 소스 코드 검토에서 빈 공간과 RTL 의미 방향을 확인했으며, 별도의 마우스 자동화 테스트는 수행하지 않았습니다. 최종 배포 앱의 실행과 기본 창을 닫은 후 다시 열기를 검증했고 로그에 `reopen verified: true`가 기록되었습니다.
- 변환 중에는 창 닫기와 앱 종료를 막습니다. 저장하지 않은 책갈피가 있으면 창을 닫거나 종료할 때 알립니다. 닫았다가 다시 열어도 현재 세션의 초안이 유지됩니다.
- 설정 버튼과 ⌘,는 같은 네이티브 설정 창을 사용합니다. ⌘N은 기본 창 표시, ⌘O는 이미지 추가, ⌘⇧O는 폴더 추가, ⌘E는 내보내기입니다.
- “PDF 암호화”는 오른쪽 설정 패널에서 “문서 정보” 다음에 독립된 영역으로 배치됩니다. 기본적으로 접혀 있고 패널과 함께 스크롤됩니다. 펼치면 두 암호 설정이 바로 표시되며 팝업 패널을 사용하지 않습니다. 열기 암호와 편집 암호에는 각각 별도의 스위치, 입력 내용을 가리는 암호 필드, 확인 필드가 있습니다.
- 한 스위치를 끄면 해당 암호와 확인 값만 지워지며, 설정을 재설정하면 두 쌍 모두 지워집니다. 잘못된 암호, 확인 값 불일치, 동일한 두 암호는 내보내기를 차단합니다. 두 스위치를 모두 끄면 일반 PDF를 내보냅니다. 접거나 펼치는 동작은 보호 설정을 바꾸지 않습니다.
- 두 암호는 현재 프로세스에만 보관되며 영구 설정, 기록, 로그에 저장되지 않습니다. 암호화 내보내기의 평문 임시 파일은 권한이 0700인 폴더에 두며 정상 취소 및 오류 경로에서 정리합니다. 최종적으로는 해당 모드 검증을 통과한 암호화 파일만 저장하며, 실패 시 암호화되지 않은 파일로 대체하지 않습니다.
- OCR 인식 언어는 계속해서 로컬 Vision의 지원 범위에 따라 결정됩니다. 인터페이스 언어 수로 OCR 언어 수를 추정하지 않습니다.

## 검증 범위와 한계

- 검증 컴퓨터는 Intel Mac입니다. 1.4 범용 패키지의 두 아키텍처 모두 컴파일에 성공했으나 실제 Apple Silicon 기기에서는 아직 테스트하지 않았습니다.
- 최소 배포 대상은 macOS 14이며, 이번 실제 실행 환경은 macOS 15.7.9입니다.
- JPEG XL은 네이티브 ImageIO로 디코딩합니다. 자체 생성한 테스트 샘플 5개는 손실 RGB, 무손실 RGB, RGBA 투명도, 16비트 회색조와 애니메이션을 포함합니다. 현재 시스템은 애니메이션의 첫 프레임만 반환하므로 프레임별 가져오기는 보장하지 않습니다. 앱은 JXL 인코딩 출력을 제공하지 않으며 원본 비트스트림, HDR 또는 높은 비트 심도 정보가 PDF에 그대로 보존된다고 보장하지 않습니다.
- 대규모 스캔 서적에 대한 성능 벤치마크는 수행하지 않았습니다. 모든 카메라 RAW 형식이나 모든 비표준 PDF 대상의 호환성을 보장하지 않습니다.
- 암호화에는 Apple PDFKit을 사용하며 AESV2/128비트 출력을 요구하고, 선택한 모드에 따라 암호와 권한을 검증합니다. 로컬 네이티브 쓰기 인터페이스의 17–31자 열기 암호 문제는 owner 인증에 영향을 주므로, 두 암호 모드의 열기 암호는 일괄적으로 1–16자로 제한합니다. 편집 암호와 두 단일 암호 모드는 각각 1–32자를 지원합니다. 앱은 암호학적 결과를 직접 수정하지 않으며 Unicode, 제어 문자, 선택한 모드의 길이 범위를 벗어난 입력을 거부합니다. 경계 사전 검사, owner 권한, 앞뒤 공백 보존은 모두 실제 파일 테스트로 확인했습니다. 두 암호 모드에서 17, 31, 32자인 열기 암호는 쓰기 전에 거부됩니다.
- 사용자 지정 텍스트 접두어가 있는 페이지 레이블은 현재 네이티브 경로로 안정적으로 보존할 수 없으므로 암호화를 켜면 명확한 오류를 표시합니다. 일반적인 알파벳/로마 숫자/숫자 구간별 페이지 번호, 읽기 레이아웃, 메타데이터는 왕복 테스트를 수행했습니다. 열기 암호가 필요한 파일은 앱 내 미리 보기에서 암호를 입력할 수 있으며 편집 암호만 있는 파일은 바로 미리 볼 수 있습니다. 암호화된 파일의 책갈피 편집은 여전히 지원하지 않습니다.
- 지원하지 않는 JBIG2/G4 인코딩, OCR 교정 기능, 인터페이스 다중 레이어, 일부 특수 책갈피 대상 등 현재의 제한 사항은 프로젝트 README의 “현재 제한 사항”을 참고하세요.
