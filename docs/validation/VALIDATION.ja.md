状態：**テストとビルドに合格**。記録日：2026-10-23。検証環境：Intel Mac、macOS 15.7.9、Swift 6.2.4 / Xcode。最小デプロイバージョンは macOS 14 です。

このバージョンは macOS 14 以降のネイティブ ImageIO による JPEG XL 入力と、個別の開くためのパスワードおよび編集用パスワードに対応しています。暗号化設定は右側パネル内の、初期状態で折りたたまれ、見出し行全体をクリックできるセクションにあります。58 件の XCTest をすべて実行し、全件合格、失敗 0、スキップ 0 でした。この Mac のネイティブ PDF 書き込み API では、開くためのパスワードが 17–31 文字の場合に owner パスワードが機能しなくなることを確認しています。アプリは両方のパスワードを使うモードで長さを事前検証し、この問題を回避します。安全な対応範囲は後述します。今回のログは `test-results.txt` にあります。

## 成果物

- `dist/FolioPDF.app`：ネイティブ AppKit ウインドウ、SwiftUI の画面、システムの PDFKit / Vision / ImageIO を使用します。アプリのファイル名にはバージョン番号を付けず、メタデータに記録します。
- `dist/FolioPDF-1.4-macOS.zip`：x86_64 と arm64 を含むユニバーサルアプリのパッケージです。`lipo -archs` で確認しました。
- `dist/FolioPDF-1.4-source.zip`：Xcode で開ける Swift Package のソースです。テスト、スクリプト、使用説明、画面のスクリーンショットを含みます。
- パッケージ作成スクリプトはローカルの ad-hoc 署名を使用し、`codesign --verify --deep --strict` に合格しています。Developer ID による公証は含みません。内部バージョンは 1.4（build 5）で、アプリ名は引き続き `FolioPDF.app` です。

OCR テストでは実際に生成した文字画像を使用し、出力 PDF からテキストを抽出できることと、非表示テキストがページのレンダリングを変えないことを検証します。テストは macOS のシステムサービスへアクセスできる環境で実行する必要があります。制限付き実行サンドボックスでの CoreVideo エラーを合格とは扱いません。

### 両パスワードの受け入れ条件

| モード | 通常の閲覧者 | 編集用パスワードの保持者 |
|---|---|---|
| 開くためのパスワードのみ | 空または誤ったパスワードでは開けません。正しい開くためのパスワードではすべての操作が許可されます | 独立した編集用パスワードは設定しません |
| 編集用パスワードのみ | パスワードなしで閲覧できます。内容の変更、注釈、フォーム入力、ページの整理は禁止します | 編集用パスワードで owner の全権限を取得します |
| 両方のパスワード | 開くためのパスワードで制限付きの user 権限を取得します | 編集用パスワードでファイルを直接開き、owner の全権限を取得します |

両方を有効にする場合、パスワードは異なる必要があります。3 モードとも印刷、コピー、アクセシビリティのためのアクセスを許可します。制限付きモードでは、内容変更、注釈、フォーム入力、ページの挿入／削除／回転を無効にします。権限の制限はリーダー側が尊重する必要があり、「絶対に編集できない」ことの保証にはなりません。

使用できるのは印字可能な ASCII 文字だけです。安全に対応する長さは、開くためのパスワードのみでは 1–32 文字、編集用パスワードのみでは 1–32 文字、両方を使う場合は開くためのパスワードが 1–16 文字、編集用パスワードが 1–32 文字です。この条件付き制限は画面に明示し、書き出し前の検証で適用します。範囲外ではエラーとし、パスワードの切り詰め、先頭・末尾のスペースの変更、保護を弱めた出力は行いません。

開いた状態の PDF に `unlock(withPassword:)` を呼び出すと、owner パスワードが誤っていても `true` が返る場合があります。そのため、検証では `permissionsStatus` とすべての権限ビットを確認します。制限付き reader は user/51、owner は owner/255、開くためのパスワードのみの reader は user/255 です。編集用パスワードのみのファイルは自動的に開くため、履歴用のページ数の取得に owner による解除は不要です。

## 画面と言語

- 現在のリソースは 292 項目 × 16 言語で、実際の画面の文言は 281 項目です。`check-localization.py` に合格し、パッケージ内の言語リソースはソースファイルとバイト単位で一致しています。
- 初期状態ではシステムに従います。言語の順序は利用者の指定どおりです：简体中文、English、繁體中文、日本語、한국어、Français、Deutsch、Español、Italiano、Português (Brasil)、Русский、العربية、हिन्दी、Türkçe、Nederlands、Polski。
- アラビア語ではメインウインドウと設定ウインドウの両方が RTL レイアウトになります。ファイル名、画像、PDF の内容は変更しません。ブックマークの TAB 区切りテキストエディターは LTR を維持し、インターフェースファイルの編集上の意味が変わらないようにしています。
- 今回はアプリを再起動し、実際の NSView をレンダリングして、中国語のライト表示での初期折りたたみ状態と両パスワードの展開、長いドイツ語文言のダーク表示、アラビア語 RTL、編集用パスワードのみの状態を確認しました。入力欄と説明は適切に折り返され、重なりや文字の欠落は見られませんでした。表示領域を超える内容は右側パネルと一緒にスクロールします。スクリーンショットは下表にあります。
- 「書類の情報」「PDF 暗号化」「余白と解像度」などの折りたたみ見出しは、行全体を Button とし、ラベルを横幅いっぱいに広げて長方形のクリック領域を定義しています。左側のワークスペース切り替えと下部の設定ボタンもクリック領域を拡大しました。ソースレビューでは空白部分と RTL の意味上の方向を確認しましたが、独立したマウス自動操作テストは行っていません。最終配布アプリの起動と、メインウインドウを閉じた後の再表示を検証し、ログには `reopen verified: true` を記録しています。
- 変換中はウインドウを閉じる操作とアプリの終了を禁止します。未保存のブックマークがある場合は、閉じる／終了する前に確認します。閉じて再度開いても、現在のセッションの下書きを保持します。
- 設定ボタンと ⌘, は同じネイティブ設定ウインドウを開きます。⌘N はメインウインドウの表示、⌘O は画像の追加、⌘⇧O はフォルダの追加、⌘E は書き出しです。
- 「PDF 暗号化」は右側設定パネルの「書類の情報」の後に独立して配置し、初期状態では折りたたまれ、パネルと一緒にスクロールします。クリックして展開すると、ポップオーバーを使わず 2 組のパスワード設定をその場に表示します。開くためのパスワードと編集用パスワードには、それぞれ独立したスイッチ、入力を隠すパスワード欄、確認欄があります。
- 片方のスイッチをオフにすると、その組のパスワードと確認値だけを消去し、設定リセットでは両組を消去します。無効なパスワード、確認値の不一致、両パスワードの一致があると書き出しを禁止します。両方をオフにすると通常の PDF を出力します。折りたたみ状態の変更は保護設定を変えません。
- 2 種類のパスワードは現在のプロセス内にだけ保持し、永続設定、履歴、ログには書き込みません。暗号化出力時の平文の一時ファイルは権限 0700 のフォルダに置き、通常のキャンセルとエラー処理で削除します。選択したモードの検証に合格した暗号化ファイルだけを最終出力し、失敗時に非暗号化ファイルへ切り替えることはありません。
- OCR の認識言語は引き続きその Mac の Vision が対応する範囲で決まります。画面の言語数から OCR の対応言語数を推測することはできません。

## 検証範囲の限界

- 検証マシンは Intel Mac です。1.4 のユニバーサルパッケージは両アーキテクチャでビルドに成功しましたが、Apple Silicon の実機ではまだテストしていません。
- 最小デプロイターゲットは macOS 14 で、今回実際に実行した環境は macOS 15.7.9 です。
- JPEG XL はネイティブ ImageIO でデコードします。自作のテストサンプル 5 個で、非可逆 RGB、可逆 RGB、RGBA の透明度、16 ビットグレースケール、アニメーションを検証しています。現在のシステムはアニメーションの最初のフレームしか返さないため、フレームごとの読み込みは保証しません。JXL 形式へのエンコード出力は提供せず、元のビットストリーム、HDR、高ビット深度情報が PDF 内にそのまま保持されることも保証しません。
- 大規模なスキャン書籍の性能ベンチマークは行っていません。すべてのカメラ RAW 形式や、あらゆる非標準 PDF 移動先との互換性は保証しません。
- 暗号化には Apple PDFKit を使用し、AESV2/128 ビットの出力を要求して、モードごとのパスワードと権限を確認します。開くためのパスワードが 17–31 文字の場合のネイティブ書き込み API の問題は owner 認証に影響するため、両パスワードのモードでは開くためのパスワードを一律 1–16 文字に制限します。編集用パスワードと、どちらか片方だけを使うモードは 1–32 文字に対応します。アプリ自身が暗号処理の結果を書き換えて修復することはありません。Unicode、制御文字、選択したモードの長さ制限を超える入力を拒否します。境界の事前検証、owner 権限、先頭・末尾のスペースの維持は実ファイルでテストし、両パスワードのモードでは開くためのパスワードの長さ 17、31、32 を書き込み前に拒否します。
- 独自の文字接頭辞を含むページラベルは現在のネイティブ処理では安定して保持できず、暗号化を有効にすると明示的にエラーになります。通常のアルファベット／ローマ数字／数字による区間別ラベル、閲覧レイアウト、メタデータは往復変換テストを行っています。開くためのパスワードが必要なファイルはアプリ内プレビューで入力でき、編集用パスワードのみのファイルはそのままプレビューできます。暗号化ファイルのブックマーク編集は引き続き非対応です。
- 未対応の JBIG2/G4 エンコード、OCR 校正機能、インターフェースの多層画像、一部の特殊なブックマーク移動先などの制限は、プロジェクト README の「現在の制限」を参照してください。
