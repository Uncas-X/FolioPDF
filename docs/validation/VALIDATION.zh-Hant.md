### 雙密碼驗收條件

| 模式 | 一般閱讀者 | 編輯密碼持有者 |
|---|---|---|
| 只啟用開啟密碼 | 空密碼和錯誤密碼不能開啟；正確開啟密碼獲得全部操作權限 | 未設定獨立編輯密碼 |
| 只啟用編輯密碼 | 不需密碼即可閱讀；禁止修改內容、註解、填寫表單和頁面整理 | 編輯密碼獲得 owner 全權限 |
| 同時啟用兩種密碼 | 開啟密碼獲得 user 受限權限 | 編輯密碼可直接開啟檔案並獲得 owner 全權限 |

兩種密碼同時啟用時必須不同。三種模式均允許列印、複製和輔助使用；受限模式關閉內容修改、註解、表單填寫以及頁面插入/刪除/旋轉。權限限制需要閱讀器遵守，不能作為“絕對不可修改”的保證。

密碼僅接受可列印 ASCII 字元，安全支援範圍為：只開啟密碼 1–32 字元；只編輯密碼 1–32 字元；雙密碼模式的開啟密碼 1–16 字元、編輯密碼 1–32 字元。雙密碼模式的條件限制在介面明確提示，並在匯出預檢中執行；超出範圍直接報錯，不截斷密碼、不改變首尾空格、不降級輸出。

已開啟的 PDF 呼叫 `unlock(withPassword:)` 時，即使 owner 密碼錯誤也可能回傳 `true`，因此驗收必須檢查 `permissionsStatus` 和全部權限位元：受限 reader 為 user/51，owner 為 owner/255；只開啟密碼的 reader 為 user/255。只編輯密碼的檔案自動開啟，歷史紀錄頁數讀取不需要 owner 解鎖。

## 驗證邊界

- 驗證機器為 Intel Mac；1.3 通用包的兩種架構均編譯成功，尚未在 Apple Silicon 實機測試。
- 最低部署目標是 macOS 14；本次實際執行環境為 macOS 15.7.9。
- 沒有作大規模掃描書籍的效能基準測試，也不承諾任意相機 RAW 格式或任意非標準 PDF 目標的相容性。
- 加密使用 Apple PDFKit，要求輸出 AESV2/128 位元，並按所選模式核驗密碼及權限。本機原生寫入 API 的 17–31 字元開啟密碼問題影響 owner 認證，因此雙密碼模式統一限制開啟密碼為 1–16 字元；編輯密碼及兩種單密碼模式各支援 1–32 字元。應用程式不自行修補密碼學結果，拒絕 Unicode、控制字元及超出所選模式長度邊界的輸入；邊界預檢、owner 權限和首尾空格保留均有實際檔案測試；雙密碼開啟密碼長度 17、31、32 會在寫入前拒絕。
- 帶自訂文字前綴的頁碼標籤無法透過目前原生流程可靠保留，開啟加密時明確報錯；一般字母/羅馬/數字分段頁碼、閱讀版面配置及中繼資料均有往返測試。需要開啟密碼的檔案在應用程式內預覽時可輸入密碼；僅編輯密碼的檔案可直接預覽。加密檔案仍不支援書籤編輯。
- 與舊軟體的差異，包括 JBIG2/G4 編碼、舊版 OCR 校對、介接多圖層和部分特殊書籤目標，詳見專案 README 的“與舊版的明確差異”。
